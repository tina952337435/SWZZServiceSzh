# 市级应急响应接口说明

## 1. 接口概述

本文档描述市级应急响应数据对接接口的设计和实现方式，包含 Token 获取、当前市级应急响应查询和历史市级应急响应查询三个接口。所有接口统一采用 JSON 格式进行请求和响应，业务接口通过 Token 认证保障数据安全。

## 2. 通用说明

### 2.1 接口规范

- 接口类型：HTTP 接口，POST 方式
- 接口基础地址：`http://{host}:{port}/`（具体地址由我方提供）
- 请求格式：`application/json`
- 响应格式：`application/json`

### 2.2 认证方式

1. **强制认证**：除获取 Token 接口外，所有业务接口均需 Token 认证，无有效 Token 无法调用。
2. **Token 获取**：首先调用"获取 Token 接口"（见 3.1 节），提交我方提供的用户名和密码，获取有效 Token。
3. **Token 使用**：获取 Token 后，需将其设置在后续接口的请求头 `Authorization` 字段中。
4. **Token 有效期**：Token 具有有效期，过期后自动失效，需重新调用获取 Token 接口刷新。

### 2.3 通用响应字段说明

所有业务接口（应急响应查询接口）的响应包含以下基础字段，通过基础字段可判断接口调用状态：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| issuccess | boolean | 接口调用结果：true=调用成功，false=调用失败 |
| message | string | 接口调用提示信息，成功时返回"操作成功" |
| total | number | 总记录数，无数据时为 0 |
| data | object/array | 接口返回的核心业务数据，具体格式见各接口说明 |
| elapsetime | number | 接口耗时（毫秒） |

> **注意**：获取 Token 接口（3.1 节）的响应字段与上述业务接口略有不同，详见该节说明。

## 3. 接口详细说明

### 3.1 获取 Token 接口

**功能说明**：通过提交我方提供的用户名和密码，获取接口调用的访问 Token。该 Token 是所有后续业务接口调用的唯一凭证，无需认证即可调用本接口。

#### 3.1.1 接口信息

| 项目 | 内容 |
|------|------|
| 请求路径 | `SWZZ_DATA_employee/GetToken` |
| 请求方式 | POST |
| 请求格式 | application/json |
| 认证方式 | 无需认证（唯一不需要携带 Token 即可调用的接口） |

#### 3.1.2 请求参数

请求体为 JSON 格式，以下字段均为必填项，缺少任一字段将导致获取失败：

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| USERNAME | string | 是 | 用户名，由我方提供 |
| PWD | string | 是 | 密码，与用户名对应 |

**请求示例**：

```json
{
  "USERNAME": "thirdparty_user",
  "PWD": "xxxxxxxxx"
}
```

#### 3.1.3 响应参数

| 字段名 | 类型 | 说明 |
|--------|------|------|
| success | string | 调用结果："true"=成功，"false"=失败 |
| Message | string | 提示信息，成功时返回"成功"，失败时返回"失败" |
| total | number | 1 |
| data | string | Token 值，后续所有业务接口需将此值放入请求头 Authorization 字段 |

#### 3.1.4 响应示例

**成功响应**：

```json
{
  "total": 1,
  "data": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "Message": "成功",
  "success": "true"
}
```

**失败响应**：

```json
{
  "total": 1,
  "data": "",
  "Message": "失败",
  "success": "true"
}
```

### 3.2 当前市级应急响应接口

**功能说明**：获取当前正在生效的市级应急响应信息，包括响应级别、响应类型、发布编号、发布时间、发布内容等。

#### 3.2.1 接口信息

| 项目 | 内容 |
|------|------|
| 请求路径 | `SWZZ_DATA_emergency_response/getSJYJXY_CURRENT` |
| 请求方式 | POST |
| 请求格式 | application/json |
| 认证方式 | Token 认证，请求头携带有效 Token |

#### 3.2.2 请求参数

该接口无需传递业务参数，提交空 JSON 对象即可。同时需在请求头中携带 `Authorization` 字段，字段值为"获取 Token 接口"（3.1 节）返回的 data 值（Token）。

**请求头示例**：

```
Authorization: eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

**请求体示例**：

```json
{}
```

#### 3.2.3 响应参数

响应数据中，`data` 为当前市级应急响应信息数组（通常为 1 条记录，也可能有多条或为空），每条记录的字段说明如下：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| ID | string | 唯一标识 |
| YJD_NUMBER | string | 响应发布编号 |
| START_TIME | string | 响应发布时间，格式为：yyyy-MM-dd HH:mm:ss |
| SIGNAL_STAGE | string | 响应状态 |
| SIGNAL_LEVEL | string | 响应级别（如：Ⅳ级、Ⅲ级、Ⅱ级、Ⅰ级） |
| SIGNAL_CATEGORY | string | 响应类型（如：防汛、防台等） |
| EARLY_WARNING_NUM | number | 本年度预警序号 |
| TITLE | string | 响应标题 |
| CONTENT | string | 响应发布内容 |
| QXTYJ_DATE | string | 气象预警时间，格式为：yyyy-MM-dd HH:mm:ss |

#### 3.2.4 响应示例

**成功响应**：

```json
{
  "total": 1,
  "pagesize": 0,
  "pagetotal": 0,
  "pageindex": 0,
  "data": [
    {
      "ID": "20250728001",
      "YJD_NUMBER": "沪汛办〔2025〕15号",
      "START_TIME": "2025-07-28 08:00:00",
      "SIGNAL_STAGE": "响应中",
      "SIGNAL_LEVEL": "Ⅲ级",
      "SIGNAL_CATEGORY": "防汛",
      "EARLY_WARNING_NUM": 15,
      "TITLE": "关于启动防汛防台Ⅲ级应急响应的通知",
      "CONTENT": "受强降雨影响，预计未来24小时...",
      "QXTYJ_DATE": "2025-07-28 06:30:00"
    }
  ],
  "message": "操作成功",
  "issuccess": true,
  "elapsetime": 125,
  "datasize": 1,
  "expand": null
}
```

**无数据响应**：

```json
{
  "total": 0,
  "pagesize": 0,
  "pagetotal": 0,
  "pageindex": 0,
  "data": [],
  "message": "操作成功",
  "issuccess": false,
  "elapsetime": 98,
  "datasize": 0,
  "expand": null
}
```

### 3.3 历史市级应急响应接口

**功能说明**：根据时间范围和分页参数，查询历史市级应急响应记录。该接口支持按时间段检索已发布或已解除的市级应急响应信息。

#### 3.3.1 接口信息

| 项目 | 内容 |
|------|------|
| 请求路径 | `SWZZ_DATA_emergency_response/getSJYJXY` |
| 请求方式 | POST |
| 请求格式 | application/json |
| 认证方式 | Token 认证，请求头携带有效 Token |

#### 3.3.2 请求参数

请求体为 JSON 格式，同时需在请求头中携带 `Authorization` 字段。

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| startdate | string | 是 | 查询开始时间，格式为：yyyy-MM-dd HH:mm:ss |
| enddate | string | 是 | 查询结束时间，格式为：yyyy-MM-dd HH:mm:ss |
| pageindex | string | 否 | 页码，从 1 开始，不传默认为 1 |
| pagesize | string | 否 | 每页记录条数，不传默认返回全部数据 |

**请求示例（分页查询）**：

```json
{
  "startdate": "2025-01-01 00:00:00",
  "enddate": "2025-07-28 23:59:59",
  "pageindex": "1",
  "pagesize": "10"
}
```

**请求示例（查询全部）**：

```json
{
  "startdate": "2025-01-01 00:00:00",
  "enddate": "2025-07-28 23:59:59"
}
```

#### 3.3.3 响应参数

响应数据中，`data` 为历史市级应急响应信息数组，每条记录的字段与"当前市级应急响应接口"（3.2 节）一致：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| ID | string | 唯一标识 |
| YJD_NUMBER | string | 响应发布编号 |
| START_TIME | string | 响应发布时间，格式为：yyyy-MM-dd HH:mm:ss |
| SIGNAL_STAGE | string | 响应状态 |
| SIGNAL_LEVEL | string | 响应级别（如：Ⅳ级、Ⅲ级、Ⅱ级、Ⅰ级） |
| SIGNAL_CATEGORY | string | 响应类型（如：防汛、防台等） |
| EARLY_WARNING_NUM | number | 本年度预警序号 |
| TITLE | string | 响应标题 |
| CONTENT | string | 响应发布内容 |
| QXTYJ_DATE | string | 气象预警时间，格式为：yyyy-MM-dd HH:mm:ss |

> **注意**：分页信息通过响应中的 `total`（总记录数）、`pageindex`（当前页码）、`pagesize`（每页条数）、`pagetotal`（总页数）字段返回，调用方可根据这些字段判断是否需要继续请求下一页数据。

## 4. 调用流程建议

1. **获取 Token**：调用 `SWZZ_DATA_employee/GetToken`（3.1 节），使用我方提供的用户名和密码获取 Token。
2. **查询当前响应**：调用 `getSJYJXY_CURRENT`（3.2 节），获取当前生效的市级应急响应数据。
3. **查询历史响应**：调用 `getSJYJXY`（3.3 节），按时间段和分页查询历史应急响应记录；根据返回的 `total` 和 `pagetotal` 判断是否需要翻页。
4. **Token 过期处理**：若接口返回认证失败，需重新获取 Token 后重试。

## 5. 注意事项

1. 所有时间字段格式统一为 `yyyy-MM-dd HH:mm:ss`。
2. 调用 `getSJYJXY` 接口时，`startdate` 和 `enddate` 为必传参数，缺少会返回错误；`pageindex` 和 `pagesize` 为可选参数，不传则默认返回全部数据。
3. 当前市级应急响应接口（`getSJYJXY_CURRENT`）返回的是当前正在生效的响应数据，可能返回空数组（表示当前无生效的应急响应）。
4. Token 请妥善保管，不要在客户端代码中硬编码暴露。
5. 请求头 `Authorization` 的值直接填写 Token 字符串即可，无需加 "Bearer" 前缀。
